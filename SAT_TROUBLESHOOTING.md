## 7. Диагностика

### 7.1. Порядок проверки: от мастера к сателлиту

Каждая следующая ступень опирается на предыдущую — проверяйте по порядку.

1. **Мастер отвечает.** Откройте в браузере
   `<адрес веб-приложения>?action=health`. Ожидается
   `{"ok":true,"service":"BOM CONTROL V12",…}`.
2. **Секрет задан.** В том же ответе `"tokenConfigured": true`. Если `false` —
   в мастере: **BOM CONTROL V12 → 🔐 Задать/сменить секрет отборщиков**.
3. **Права отборщика.** Ответ `forbidden:no_role` — вашего адреса нет в
   `V12_ROLE_MAP` либо роль не `warehouse`/`production`/`admin`.
4. **Секрет совпадает.** `unauthorized` — секрет в личном файле отличается.
   Возьмите актуальный (мастер отдаёт его всплывающим сообщением).
5. **Список приходит.** «Обновить список» наполняет лист. Если нет — смотрите
   уведомление справа от таблицы: там текст ошибки.
6. **Отправка работает.** Поставьте одну галочку, нажмите «ПРИМЕНИТЬ» и
   проверьте в мастере лист `PICKING_BATCHES` — должна появиться строка с вашим
   адресом.

### 7.2. Таблица неисправностей

| Симптом | Причина | Что делать |
|---|---|---|
| `token_not_configured` | На мастере не задан секрет | Мастер → «Задать/сменить секрет отборщиков» |
| `unauthorized` | Секрет не совпадает | Ввести актуальный секрет в настройках личного файла |
| `forbidden:no_role` | Нет адреса в `V12_ROLE_MAP` | Администратор добавляет адрес с ролью `warehouse`/`production` |
| `actor_required` | Не заполнен e-mail | «Настройки файла отбора», шаг 3/3 |
| «Файл не настроен: укажите …» | Не заполнены настройки | «Настройки файла отбора» |
| «Нет связи с мастером» | Неверный адрес, нет сети, взято `/dev` | Вставить адрес развёртывания (заканчивается на `/exec`) |
| «Мастер вернул код 401/403» | Неверный доступ развёртывания | В мастере: Доступ = «Все, у кого есть аккаунт Google» |
| «Мастер синхронизируется» | Идёт полная синхронизация | Подождать 1–2 минуты и повторить отправку |
| `batch_too_large` | Позиций больше, чем допускает мастер | Отправить лот частями |
| Галочки исчезли | Их снял тот же отборщик после применения лота | Проверить `PICKING_BATCHES` |
| Список пуст при выбранном проекте | В проекте нет активных непереданных позиций | Проверить проект или выбрать «(Все проекты)» |
| Кнопка не реагирует | Скрипт не привязан к картинке | Правый клик по кнопке → «Назначить скрипт» → `satSubmit` |
| Список не обновляется при открытии | Установленные триггеры не созданы/удалены | Повторить «Установка (лист, триггеры, кнопка)» |
| Проект «занят» давно | Захват остался от прошлого периода | Личный файл: «Освободить проект»; мастер: «🔓 Освободить все захваты проектов» |

### 7.3. Проверки на стороне мастера

| Функция меню | Что показывает |
|---|---|
| 🔎 Диагностика V12 | наличие листов, число позиций/BOM, `pendingEdits`, `pendingBatches`, `activeClaims`, `syncInProgress`, `tokenConfigured` |
| 🧩 Проверка консистентности | соответствие BOM ↔ позиции, дубликаты `Position ID`, лоты в статусе `PENDING`, просроченные захваты, расхождения склада |
| 🧾 Журнал лотов | последние 20 лотов: номер, проект, отборщик, статус, применено/всего |
| 📦 Обработать лоты отборщиков | немедленно применить лоты, оставшиеся в статусе `PENDING` |
| 🧹 Схлопнуть дубли очереди | убрать повторные намерения по одному `Position ID` |

### 7.4. Как читать `PICKING_BATCHES`

| Колонка | Значение |
|---|---|
| `Batch ID` | номер лота от сателлита (`SAT-…`) или `MANUAL` для локального применения в мастере |
| `Отправлено` | когда мастер принял лот |
| `Отборщик` | адрес из настроек личного файла (проверен по списку ролей) |
| `Статус` | `PENDING` — в обработке, `APPLIED` — применён, `PARTIAL` — применён частично, `FAILED` — не применён |
| `Применено позиций` / `Не применено` | сколько отметок прошло и сколько нет |
| `Ошибка` | причина по непринятым позициям |

### 7.5. Ротация секрета

Чтобы отозвать доступ у старого файла, не меняя роли:

1. Мастер → **🔐 Задать/сменить секрет отборщиков** (секрет меняется сразу).
2. Раздать новый секрет действующим отборщикам.
3. Остальные личные файлы получат `unauthorized` и работать не смогут.

### 7.6. Если результаты не сходятся

1. Мастер → **🔎 Диагностика V12**: если `syncInProgress = true`, подождите.
2. Мастер → **🧩 Проверка консистентности**: покажет лоты в `PENDING`,
   просроченные захваты и расхождения склада.
3. Мастер → **📦 Обработать лоты отборщиков**: доберёт отложенные лоты.
4. В личном файле — «Обновить список» и «Статус последнего лота».

### 7.7. Ограничения, принятые сознательно

Эти места работают «как есть» — по решению владельца системы; они
задокументированы, чтобы о них знали, а не выясняли случайно.

1. **Двойная выдача одного физического материала не блокируется.** Склад не
   участвует в расчёте доступности (`availableForProduction =
   reserved + realDelivery`), поэтому система не может доказать, что один и
   тот же материал не будет выдан по двум проектам. Риск виден через захваты
   проектов (`PICKING_CLAIMS`).
2. **Складской остаток может уйти ниже нуля** — значение не «зажимается».
   Несоответствия показываются в «Проверке консистентности».
3. **Мягкий захват проекта не блокирует работу.** Двое на одном проекте — это
   предупреждение, а не запрет.
