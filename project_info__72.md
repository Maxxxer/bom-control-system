## 2. Контракт транспорта (сателлит ↔ мастер)

**Запрос** — `POST` на адрес веб-приложения мастера, тело — JSON:

```json
{
  "token": "PBT-…",
  "actor": "picker@example.com",
  "action": "submit",
  "project": "1234.АБВ",
  "batchId": "SAT-1712345678901",
  "spreadsheetId": "<ID личного файла>",
  "items": [ { "positionId": "BOM-0001:ART-77|Siemens", "checked": true } ]
}
```

**Действия (`WEB_ACTIONS`)**: `rows` (строки отборки), `submit` (лот), `status` (журнал лотов), `claim` / `release` (захват проекта), `pickers` (доступные проекты и отборщики), `health` (проверка связи, только `GET`).

**Коды ошибок**: `unauthorized` (нет/неверный секрет), `actor_required`, `forbidden:<роль>`, `unknown_action:<имя>`, `project_required`, `batch_id_required`, `batch_too_large`, `sync_in_progress`, `use_post`.

**Ответ на `submit`**: `{ ok, batchId, status, applied, failed, total, errors[], error, retryAfterSec, warning }`.
`warning` — мягкий захват: проект уже отбирает другой пользователь, но работа НЕ блокируется.

## 3. Что именно решено (конфликты A1–A4, B4, B5, B7)

| Конфликт | Как решён |
|---|---|
| **A1** общий фильтр проекта (одна ячейка B1) | у каждого отборщика свой файл и свой B1; фильтр действует только в личном файле |
| **A2** пересборка листа стирает чужие неприменённые галочки | обновление сателлита пишет только колонки 1–12 и **не трогает** колонку галочек; привязка галочки — по `Position ID`, а не по номеру строки |
| **A3** «Применить» сливает чужие намерения | применение идёт **только своей партии**: `v12ApplyBatch(batchId)` → `v12DrainPendingEdits(batchId)` |
| **A4** молчаливая потеря намерения при занятом локе | намерение фиксируется атомарной дозаписью `appendRow`; при занятом локе отметка отборщика не теряется |
| **B4** двое взяли один проект | `PICKING_CLAIMS` + мягкий захват с TTL: предупреждение вместо отказа |
| **B5** повторная отправка одного лота | идемпотентность по `BATCH_ID`: повтор возвращает прежний результат, ничего не применяя дважды |
| **B7** отборщик не узнаёт результат | результат приходит в ответе и показывается уведомлением в личном файле |

## 5. Что нужно сделать руками (в Google Apps Script)

Автоматически проверено только то, что можно проверить локально. Дальше — ручные шаги владельца:

1. `clasp push` — выгрузить мастер (файлы `sat_*`, `SAT_*`, `_local_tests/**`, `_tmp_*` исключены через `.claspignore`).
2. Мастер: **«BOM CONTROL V12» → «⚙ Установка V12»** — создать `PICKING_BATCHES` и `PICKING_CLAIMS`, дописать заголовки `PENDING_EDITS`.
3. Мастер: **«🔐 Задать/сменить секрет отборщиков»** — получить код `PBT-…`.
4. Мастер: развернуть веб-приложение (**Запуск от имени: я**, **Доступ: любой пользователь с аккаунтом Google**), проверить `?action=health`.
5. Мастер: заполнить `V12_ROLE_MAP` (отборщики — `WAREHOUSE`/`PRODUCTION`); при желании закрыть лист ОТБОРКА (**«🛡 Поставить защиту на лист ОТБОРКА»**).
6. Каждому отборщику: копия личного файла → `clasp push` сателлита в свой проект → **«Отбор» → «⚙ Настройки файла отбора»** (адрес мастера, секрет, свой e-mail) → **«Отбор» → «🧩 Установка (лист, триггеры, кнопка)»**.
7. Проверка: отметить 1–2 голубые позиции → «ПРИМЕНИТЬ» → в `PICKING_BATCHES` появляется лот со статусом `APPLIED`, позиции уходят из списка.

## 6. Что осталось за рамками (осознанно)

1. **Физический дефицит (A7).** Сателлиты разделяют рабочее место, но не материал: двое могут «успешно» выдать один и тот же материал по разным BOM. Нужна политика выдачи (квазирезерв: `warehouseQty − уже обещанное ≥ выдаваемое`).
2. **Массовый откат лота.** Возврат ошибочной передачи — по одной позиции (меню мастера), отката по `BATCH_ID` нет.
3. **Отложенное применение.** Сейчас `submit` применяет лот сразу; при большом числе отборщиков имеет смысл копить лоты и применять пачкой.
4. **Мелкое:** в `sat_config.js` блок комментария `COLORS` не выровнен (на читаемость не влияет); в `REGULATIONS.md` пункты меню сателлита названы по ключевым словам («Настройки», «Установка», «О системе») — точные подписи: «⚙ Настройки файла отбора», «🧩 Установка (лист, триггеры, кнопка)», «❓ О программе».
