# Личный файл отборщика (сателлит) — инструкция

Инструкция для администратора системы и для каждого отборщика.
Отвечает на вопрос «как сделать так, чтобы несколько отборщиков работали
одновременно и не мешали друг другу».

---

## 1. Зачем это нужно

Раньше ОТБОРКА была **одним** листом в мастер-таблице, и это создавало три
неустранимых конфликта:

| Что было | Чем это мешало |
|---|---|
| Фильтр проекта — одна ячейка `B1` на всех | Двое не могут смотреть разные проекты: смена фильтра одним сотрудником меняет лист у всех |
| Пересборка листа перезаписывала тело | Нажатие «ПРИМЕНИТЬ» (или синхронизация) **стирало чужие неприменённые галочки** всем сразу |
| Очередь правок `PENDING_EDITS` — общая | Нажавший «ПРИМЕНИТЬ» применял **и чужие незавершённые** отметки |

Теперь каждый отборщик работает в **своём** файле (сателлите): у него свой
фильтр, свои галочки, своя кнопка «ПРИМЕНИТЬ». В мастер уходит только готовый
**лот** — список отмеченных позиций. Мастер применяет ровно этот лот.

```
   Личный файл отборщика A                    МАСТЕР
   ┌──────────────────────┐            ┌────────────────────────┐
   │ B1: проект 1234      │  rows  ←── │ POSITION_STATE         │
   │ галочки …            │            │  (единственный источник│
   │ [ПРИМЕНИТЬ] ─────────┼── submit → │   истины)              │
   └──────────────────────┘            │ PENDING_EDITS + лот    │
   Личный файл отборщика B             │ PICKING_BATCHES/CLAIMS │
   ┌──────────────────────┐            └────────────────────────┘
   │ B1: проект 5678      │                        ↑
   │ галочки …            │ ────── submit ─────────┘
   └──────────────────────┘
```

---

## 2. Что где лежит

**Мастер** (основной проект, таблица-мастер):

| Файл | Роль |
|---|---|
| `v12_webapp.js` | веб-API: `rows`, `submit`, `status`, `claim`, `release`, `pickers` |
| `v12_batches.js` | лоты отборки, мягкие захваты проектов, применение лота |
| `v12_queue.js` | очередь намерений, привязка намерений к лоту, схлопывание дублей |
| `v12_projections.js` | `v12BuildPickingRecords` — **тот же** алгоритм строк, что и в сателлите |

**Личный файл отборщика** (отдельный проект, папка `_satellite/`):

| Файл | Роль |
|---|---|
| `sat_config.js` | настройки: колонки, фильтр `B1`, свойства, палитра |
| `sat_api.js` | единственная точка сетевых вызовов к мастеру |
| `sat_sheet.js` | лист-витрина; галочки сопоставляются по `Position ID` |
| `sat_refresh.js` | «Обновить список» + мягкий захват проекта |
| `sat_submit.js` | кнопка «ПРИМЕНИТЬ»: собрать галочки и отправить лотом |
| `sat_menu.js` | меню «Отбор», настройки, кнопка |
| `sat_install.js` | установка: лист, кнопка, триггеры |
| `appsscript.json` | манифест (нужен доступ к внешним запросам) |

## 3. Настройка мастера (делает администратор, один раз)

### 3.1. Развернуть код мастера

```bash
clasp push
```

> Файлы сателлита (`_satellite/`) при этом НЕ выгружаются в мастер: они
> исключены в `.claspignore`. Это намеренно — иначе функции сателлита попали бы
> в мастер-проект.

### 3.2. Проверить часовой пояс и разрешения

В `appsscript.json` мастера должны быть области:
`.../auth/spreadsheets`, `.../auth/script.scriptapp`,
`.../auth/script.external_request`. Последняя обязательна: без неё мастер не
сможет отвечать сателлитам.

### 3.3. Выполнить установку

В мастер-таблице: меню **BOM CONTROL V12 → ⚙ Установка V12**.
Установка создаст два новых листа:

* `PICKING_BATCHES` — журнал лотов (кто, когда, по какому проекту, что применено);
* `PICKING_CLAIMS` — мягкие захваты проектов;

и расширит `PENDING_EDITS` до 12 колонок (`Batch ID`, `Проект`).

### 3.4. Задать секрет отборщиков

Меню **BOM CONTROL V12 → 🔐 Задать/сменить секрет отборщиков**.
Появится всплывающее сообщение со **свежим секретом** вида
`PBT-xxxxxxxx-xxxx-…`. **Скопируйте его** — он понадобится каждому отборщику.

> Секрет хранится только в свойствах скрипта мастера и никогда не попадает в
> код, журналы и аудит. Смена секрета немедленно отключает все старые личные
> файлы: им придётся ввести новый секрет.

### 3.5. Развернуть веб-приложение

1. В редакторе Apps Script мастера: **Развернуть → Новое развёртывание**.
2. Тип: **Веб-приложение**.
3. **Запуск от имени**: *От вашего имени* (`USER_DEPLOYING`) — обязательно:
   мастер должен иметь доступ к своей таблице, даже когда его вызывает
   отборщик.
4. **Доступ**: *Все, у кого есть аккаунт Google*.
5. Скопировать **URL веб-приложения** (заканчивается на `/exec`).

Проверка: откройте этот URL в браузере с добавленным `?action=health`.
Должен вернуться JSON вида
`{"ok":true,"service":"BOM CONTROL V12",…}`.

### 3.6. Убедиться, что отборщики есть в списке ролей

В `v12_roles.js` (`V12_ROLE_MAP`) у каждого отборщика должна быть роль
`warehouse` или `production` (или `admin`). Мастер пускает к отборке только
эти роли — чужой адрес получит отказ `forbidden`.

### 3.7. Привести мастерский лист ОТБОРКА в режим витрины

Меню **BOM CONTROL V12 → 🛡 Поставить защиту на лист ОТБОРКА**.
Лист получит защиту-предупреждение и надпись «Витрина. Рабочее место — личный
файл отбора».

> Защита именно **мягкая**. Жёсткий запрет сломал бы пересборку проекций:
> `v12RefreshPicking` пишет на этот же лист от имени того, кто нажал
> «ПРИМЕНИТЬ».

### 3.8. Что желательно проверить заранее

* `MASTER_SPREADSHEET_ID` (если используется в вашей конфигурации) указывает на
  мастер-таблицу;
* полная синхронизация перенесена в ночное окно (03:00) — она больше не мешает
  работе днём;
* лист `ОТБОРКА` в мастере не редактируется вручную: все отметки идут из
  личных файлов.
