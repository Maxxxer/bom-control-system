# Дубли в PENDING_EDITS при массовой отметке — причина и исправление

> Разбор сохранён в `project_info__57.md`. Дубли появились именно из-за сканирующего захвата (он на каждое событие пишет ВСЕ отмеченные строки), из-за чего перекрывающиеся исполнения `onEdit` добавляют одни и те же позиции дважды.

## Что подтверждено
- Триггер **один** (`v12OnEdit`) — двойного вызова нет.
- **`v12EnqueuePendingRows` не делает `SpreadsheetApp.flush()`** после записи (в отличие от `v12DrainPendingEdits`/`v12_operations.js`).
- Писатели `PENDING_EDITS` — только `v12EnqueuePendingRows` (+ статус/очистка внутри слива под локом).

## Механизм
Сканирующий захват на каждое событие собирает намерения для **всех** стоящих галочек. При массовой отметке события идут потоком и **перекрываются**:
- событие A сканирует → N отмеченных;
- событие B почти одновременно сканирует → те же N;
- по локу они идут по очереди, но второе **не видит ещё не «профлашенную»** запись первого → считает ключи новыми → **append** тех же позиций.

Раньше на событие писалось ~1 намерение (строка правки), теперь — десятки, поэтому окно перекрытия и объём совпадений выросли → «иногда задваиваются». Upsert матчит только `PENDING` и обновляет одну из совпавших строк, поэтому уже накопленные дубли не схлопываются.

## Надёжное исправление (без дублей И без потерь)
Разделить «фиксацию» и «пересборку»:

1. **Точный захват (onEdit) — только строки события.** Вернуть `v12CaptureCheckboxEdit` к обработке редактируемых строк (значение true/false из `e.values`/`e.value`); upsert по ключу идемпотентен → дубли невозможны по построению.
2. **Реконсиляция при Apply (уже есть)** — синтетические намерения (row:0), в лист ничего не пишут → потерь нет, дублей нет.
3. **Явная ПЕРЕСБОРКА очереди** — новая `v12RebuildPendingFromChecked()`: читает все отмеченные строки ОТБОРКИ/WORKING BOM и **полностью перезаписывает** множество `PENDING`-намерений (по ключу ровно одна строка; дубли схлопываются). Это **replace, а не append** → повторный вызов не плодит строк. Доступна кнопкой/меню; можно вызывать и в начале слива — тогда видимая очередь до применения полная и без дублей.
4. **`SpreadsheetApp.flush()` под локом** после записи в `v12EnqueuePendingRows` — чтобы следующее исполнение гарантированно видело строки.
5. **Дедуп на сливе** — в начале `v12DrainPendingEdits` схлопывать дубли `PENDING` по ключу (оставить последнюю, остальные пометить DONE).

## Что не надо делать
- Оставлять «полный скан + append на каждое событие» — прямой источник перекрывающихся appends.
- Полагаться на лок без `flush».
- Матчить upsert только `PENDING` (накопленные дубли не схлопнутся).

**Затронутые файлы:** `v12_queue.js` (вернуть точный захват, добавить `v12RebuildPendingFromChecked` и/или дедуп в `v12DrainPendingEdits`, `flush` в `v12EnqueuePendingRows`), при добавлении пункта меню — `v12_ui.js`/`v12_controller.js`.
