# BOM CONTROL SYSTEM V12 — Реализация Варианта D: очередь правок чекбоксов (`PENDING_EDITS`)

> **Статус:** реализовано, локальная верификация пройдена (см. §8). Требуется установка в Google Apps Script и ручная приёмка (§9).
> **Предыстория:** диагностика дефекта — `project_info__38.md`.
> **Правило задачи:** убрать окно «Система занята обновлением…», обеспечить быструю отметку чекбоксов, гарантированное сохранение отметки без сброса, без слома бизнес-логики.

---

## 1. Что сделано (коротко)

onEdit больше **не выполняет** тяжёлую работу для чекбоксов. Он только **фиксирует намерение** строкой в новом листе `PENDING_EDITS` (быстро, без блокировки) и выходит. Применение делает:

- **немедленно** — если скриптовая блокировка свободна (`v12TryInlineDrain`), либо
- **раз в минуту** — фоновый триггер `v12ScheduledQueueDrain`,

— **пакетно**, одним пересчётом проекций.

**Результат:**
- ❌ Окно «Система занята обновлением. Повторите ввод через несколько секунд.» — **удалено из кода** (осталось только в комментариях).
- ❌ Принудительный сброс галочки (`v12RevertEdit`) при недоступности лока — **удалён**.
- ✅ Отметка **не может потеряться**: она хранится в очереди, а не в ячейке, которую перезаписывает пересборка проекции.
- ✅ Бизнес-логика (передача производству, списание склада, реальная поставка, аудит) — **не изменена**, переиспользуются существующие операции.

Охват: чекбоксы **ОТБОРКИ**, **WORKING BOM**, **«Реальная поставка» в Сводке дефицитов**. Типизированные поля (Заказано/Ожидаемая), Dashboard, POSITION_STATE/MATERIAL_STATE, фильтр B1 — как раньше.

## 4. Как теперь работает onEdit (быстрый путь)

`v12OnEdit`, сразу после проверки «наш ли это лист»:

```js
// === Быстрый путь для чекбоксов (очередь правок, Вариант D) ==========
if (v12CaptureCheckboxEdit(e, name)) {
  v12TryInlineDrain();      // применить сразу, если лок свободен
  return;                   // НИКАКИХ окон и НИКАКИХ откатов
}
```

`v12CaptureCheckboxEdit(e, sheetName)`:
1. Определяет лист/колонку/поле/право (ОТБОРКА — кол. 12; WORKING BOM — кол. 14; Сводка — кол. 12).
2. Пропускает правку дальше (`return false`), если это **не** чекбокс-колонка → обрабатывается прежней логикой. Для Сводки перехватывается **только** диапазон целиком в колонке чекбокса (чтобы не потерять ввод «Заказано»/«Ожидаемой»).
3. Проверяет право (`v12CanEditField`) **на этапе захвата** — onEdit исполняется от имени редактора. Нет права → `v12RevertEdit` + лог, в очередь не пишем.
4. Читает `Position ID` строк диапазона **одной** выборкой; для одиночной ячейки берёт значение из `e.value`.
5. Пишет строки в `PENDING_EDITS` одним вызовом (`writeValues`, без лока).

Оставшиеся ветки `v12OnEdit` (типизированные поля Сводки, Dashboard, POSITION_STATE/MATERIAL_STATE, фильтр B1) — без изменений, но в ветке «лок занят» теперь **нет** модального окна, только тихая запись в лог.

## 5. Модуль `v12_queue.js`

| Функция | Назначение |
|---|---|
| `v12CurrentActor()` / `v12WithActor(actor, fn)` | актор-контекст (реальный автор в фоне) |
| `v12BuildPendingRow` / `v12EnqueuePendingRows` / `v12EnqueuePendingEdit` | сборка и запись строк очереди |
| `v12CaptureCheckboxEdit(e, sheetName)` | быстрый путь onEdit |
| `v12HasPendingEdits()` / `v12CountPendingEdits()` | дешёвая проверка / счётчик (без лока) |
| `v12CollectPendingRowNumbers(data)` | строки со статусом `PENDING` |
| `v12ResolvePendingIntents(data)` | разбор намерений, правило **last-wins** |
| `v12ApplyRealDeliveryIntent(pid, ctx, posIndex)` | пакетное применение «реальной поставки» |
| `v12MarkPendingProcessed(rows, failed)` | пометка `DONE` / `FAILED` (+ причина) |
| `v12PurgeDonePendingEdits(maxAgeDays)` | очистка старых обработанных строк |
| `v12DrainPendingEdits()` | **основной слив** |
| `v12ScheduledQueueDrain()` | обёртка для минутного триггера |
| `v12TryInlineDrain()` | немедленный слив из onEdit, если лок свободен |

### Алгоритм слива

```
v12HasPendingEdits()? ──нет──▶ выход (дешево, без лока)
   │да
acquireScriptLock(tryOnly, 5s) ──нет──▶ выход (лок занят, повторим через минуту)
   │да
прочитать PENDING_EDITS
intents = last-wins по (SOURCE, POSITION_ID, FIELD)
ctx = { index: POSITION_STATE, materialIndex: MATERIAL_STATE, warehouseDelta, realDeliveryWrites }
для каждого намерения:
   если value=false → отмена (пропуск)
   иначе v12WithActor(user) { HANDOFF → v12MarkReceivedByProduction(pid, source, skipRefresh=true, ctx)
                              REAL_DELIVERY → v12ApplyRealDeliveryIntent(pid, ctx) }
применить складские дельты  → одним батчем (v12ApplyWarehouseDeltas)
применить записи POSITION_STATE от поставки → одним батчем
ОДИН v12RefreshProjections()
пометить все PENDING-строки DONE (или FAILED с причиной)
v12PurgeDonePendingEdits(30)
releaseLock
```

**Ключевое:** один пересчёт проекций на всю пачку (а не на каждую строку), идемпотентность (`v12MarkReceivedByProduction` → `already`; поставка — только «вверх»), устойчивость к падению (повторный слив безопасен).

## 6. RBAC и аудит в фоне (актор-контекст)

Time-driven триггер исполняется от имени владельца скрипта, поэтому:

- **Пользователь** правки фиксируется **в onEdit** (столбец `USER` очереди) и восстанавливается при применении через `v12WithActor`.
- **Права** проверяются дважды: на захвате (от имени редактора) и при применении (роль автора через `v12CurrentActor`).
- **Аудит/журнал** (`AUDIT_LOG`, `MATERIAL_HISTORY`, `EVENT_LOG`) пишут **автора отметки**, а не владельца.

Изменены только три точки: `v12Audit`, `v12LogHistory`/`v12LogEvent`, `v12GetCurrentUserRole` (+ сообщение в `v12RequireRole`) — на `v12CurrentActor()`. Вне слива поведение не меняется.

## 7. Изменения поведения (осознанные)

| Было | Стало |
|---|---|
| Быстрая отметка → окно + сброс галочки | Окно и сброс **отсутствуют** |
| Отметка применяется мгновенно (или теряется) | Применяется сразу (если лок свободен) либо **≤1 минуты** |
| Снятие галочки = «ничего не делает» | Снятие **отменяет** ещё не применённую отметку (last-wins) |
| При массовой отметке — N пересчётов | **Один** пересчёт на пачку |
| Нет записи «кто отметил» для отложенных | `USER` фиксируется, аудит корректен |

**Ограничение по замыслу:** при «редких» отметках (пауза больше длительности слива) включённый `QUEUE_INLINE_DRAIN` делает каждую правку «полной» (несколько секунд) — но **без ошибок и потерь**. Убрать это полностью можно только инкрементальным обновлением проекций (Вариант C) — вне текущего объёма.

## 9. Установка и ручная приёмка (Apps Script)

1. `clasp push`.
2. Меню **BOM CONTROL V12 → ⚙ Установка V12** (создаст лист `PENDING_EDITS`, переустановит триггеры).
3. Проверить в «Триггерах проекта» наличие `v12OnEdit`, `v12ScheduledUpdate` и **`v12ScheduledQueueDrain`** (раз в минуту).

**Сценарии приёмки:**
1. Быстро поставить 10 галочек в ОТБОРКЕ → окна нет; отметки видны; через ≤1 мин все позиции переданы, склад списан, строки исчезли из ОТБОРКИ.
2. Отметка во время часовой полной синхронизации → правка **не теряется** (фиксируется в очереди, применяется после синка).
3. Поставить и снять галочку в течение минуты → передачи **не** произошло (отмена).
4. Проверить `AUDIT_LOG`: «Пользователь» = автор отметки (не владелец скрипта).
5. `SYSTEM_LOG`: в `v12ScheduledQueueDrain` нет исключений; меню «⏱ Обработать очередь правок» работает.

## 10. Настройки и тонкая подстройка

`V12_CONFIG.SETTINGS`:
- `QUEUE_DRAIN_MINUTES: 1` — периодичность фонового слива. Увеличить (2–5) можно для экономии квоты триггеров; отметить, что задержка применения вырастет.
- `QUEUE_INLINE_DRAIN: true` — немедленный слив из onEdit, если лок свободен. `false` → только минутный триггер (правки всегда «мгновенны», но применяются ≤1 мин).
- `QUEUE_PURGE_DONE_DAYS: 30` — сколько хранить обработанные строки (аудит очереди; полноценный аудит — в `AUDIT_LOG`).

## 11. Примечания

- Очередь — **первичный источник истины** для отметок; существующий «подхват» (`v12HarvestPickingInput` / `v12HarvestDeficitInput`) остаётся как вторая линия защиты от правок в обход onEdit. Пересечение безопасно (идемпотентность).
- `v12CaptureCheckboxEdit` не берёт блокировку: операция append-only, без read-modify-write. Это ключ к тому, что отметка фиксируется даже во время часового синка.
- `PENDING_EDITS` не участвует в проекциях/Dashboard — служебный лист.
