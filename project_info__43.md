> **Основание:** проектный анализ — `project_info__42.md` (§9 рекомендация, §10 мини-план).
> **Предыстория очереди:** `project_info__39.md` (Вариант D), `project_info__41.md` (Вариант A), диагностика — `project_info__40.md`.

## 1. Что сделано (кратко)

Автоприменение правок **полностью убрано**. Теперь:

1. `onEdit` для редактируемых полей **только фиксирует намерение** строкой в листе `PENDING_EDITS` — без блокировки, без расчётов, без пересборки проекций.
2. Пользователь нажимает **«Применить изменения»** — зелёную кнопку **«ПРИМЕНИТЬ»** в верхнем левом углу рабочего листа (или пункт меню «BOM CONTROL V12») → одна locked-операция: прочитать очередь → применить все намерения пачкой → **ОДИН** пересчёт всех проекций → пометить строки `DONE`. Результат показывается **всплывающим сообщением** в правом нижнем углу окна (3 с) — без модальных окон.
3. Пока Apply не нажат, проекции **не пересобираются вообще** — окно гонки «пользователь печатает ↔ фон пересобирает лист» схлопнулось в ноль. Первопричина дефекта «быстрый ввод → сброс в 0.0» устранена структурно.

Дополнительно удалены две самые тонкие подсистемы: **harvest** (подбор необработанных правок из листов) и **инлайн-слив** (применение из `onEdit` под гейтом лока).

## 3. Как это работает

### Захват (быстрый путь, `onEdit`)

| Лист | Колонка | Поле очереди | Право |
|---|---|---|---|
| ОТБОРКА | CHECKBOX (12) | `HANDOFF` | `PICKING_CHECKBOX` |
| WORKING BOM | CHECKBOX (14) | `HANDOFF` | `WORKING_BOM_CHECKBOX` |
| Сводка дефицитов | Заказано (9) | `ORDERED_QTY` | `ORDERED_QTY` |
| Сводка дефицитов | Ожидаемая поставка (10) | `EXPECTED_DATE` | `EXPECTED_DATE` |
| Сводка дефицитов | Реальная поставка (12) | `REAL_DELIVERY` | `REAL_DELIVERY` |

- Диапазон в Сводке может охватывать **несколько** редактируемых колонок (вставка/автозаполнение) — по каждой колонке и строке фиксируется своё намерение.
- Права проверяются на этапе захвата (событие исполняется от имени редактора).
- Одиночная правка read-only ячейки Сводки **откатывается**; диапазон read-only колонок откатить нельзя (нет `oldValue`) — факт фиксируется в `SYSTEM_LOG`, значения восстановятся при ближайшем Apply.

### Применение (`v12ApplyChanges`)

```
v12ApplyChanges()
 └─ v12DrainPendingEdits()            ← лок (tryOnly, 5 с)
     ├─ v12ResolvePendingIntents()    ← last-wins по (SOURCE, POSITION_ID, FIELD)
     ├─ по каждому намерению: v12ApplyPendingIntent (от имени автора правки)
     │    ├─ HANDOFF        → v12MarkReceivedByProduction(..., skipRefresh=true, ctx)
     │    ├─ REAL_DELIVERY  → v12ApplyRealDeliveryIntent → v12SetRealDeliveryQty(...)
     │    ├─ ORDERED_QTY    → v12SetOrderedQty(..., ctx)
     │    └─ EXPECTED_DATE  → v12SetExpectedDate(..., ctx)
     ├─ batchWrite POSITION_STATE (все накопленные записи)
     ├─ v12ApplyWarehouseDeltas   (все складские дельты)
     ├─ v12RefreshProjections()   ← ОДИН пересчёт 5 проекций
     ├─ v12MarkPendingProcessed() ← DONE / FAILED + причина
     ├─ v12PurgeDonePendingEdits()← очистка старых обработанных строк
     └─ v12UpdatePendingIndicator(0)
```

Правила, которые сохранились:
- **last-wins** по `(SOURCE, POSITION_ID, FIELD)` — решает последняя строка очереди;
- для **чекбокс-полей** `VALUE=false` — это **отмена** намерения («поставил → снял» ничего не делает);
- для **типизированных** полей `0` и пустая дата — обычные значения, а не отмена;
- применение **идемпотентно** (передача — `v12MarkReceivedByProduction`; реальная поставка фиксируется только «вверх»);
- аудит/журнал получают **реального автора правки** (актор-контекст из строки очереди), а не владельца скрипта.

## 4. Индикатор «есть неприменённые изменения»

Три места, где пользователь видит, что Apply ещё не нажат:

1. **Кнопка «ПРИМЕНИТЬ»** в верхнем левом углу листа (A1, см. §5.2) — главный ориентир: она всегда на виду на «Сводке дефицитов», в «ОТБОРКЕ» и «WORKING BOM».
2. **Подпись пункта меню:** «Применить изменения (N)» — обновляется при открытии таблицы (`v12OnOpen`).
3. **Ячейка-статус** в строке 1 «Сводки дефицитов», справа от таблицы (колонка `COLUMN_COUNT.DEFICIT_SUMMARY + 2`): «Неприменённых изменений: N — кнопка «ПРИМЕНИТЬ» слева или меню «BOM CONTROL V12» → «Применить изменения»». Обновляется при фиксации каждого намерения, при открытии таблицы и сбрасывается после Apply.

Почему именно там: строку 1 пересборка проекций не трогает (`clearBody` очищает только строки 2+), поэтому индикатор не конфликтует ни с заголовками, ни с данными и не требует отдельного листа.

## 5. Интерфейс: всплывающие сообщения и кнопка «ПРИМЕНИТЬ»

### 5.1 Всплывающие сообщения (`v12Toast`)

Модальные окна из пользовательских путей убраны. Сводка о применении, результат установки, итог теста и сообщения об ошибках показываются всплывающим сообщением **в правом нижнем углу окна таблицы** (`SpreadsheetApp.getActive().toast(...)`, `v12_ui.js`), которое исчезает само:

| Событие | Сообщение | Время |
|---|---|---|
| Apply выполнен | «Применено изменений: N» | 3 с |
| Apply: часть не применилась | «Применено: N, не применено: M (см. PENDING_EDITS, колонка «Ошибка»)» | 8 с |
| Apply: очередь пуста | «Неприменённых изменений нет» | 3 с |
| Apply: лок занят | «Система занята — повторите через несколько секунд» | 3 с |
| Apply: исключение | «Ошибка применения: <текст>» | 8 с |
| `v12Install` выполнен | «Скрипт выполнен: V12 установлена, кнопка «ПРИМЕНИТЬ» поставлена» | 3 с |
| Ошибка установки | «Ошибка установки V12: <текст>» | 8 с |
| «Тест V12» | «Тест V12: ошибок N из M» (полный отчёт — в `SYSTEM_LOG`) | 3 с |
| Возврат из архива | «Позиция возвращена из архива: <ID>» / «Не удалось вернуть: <причина>» / «Position ID не указан» | 3 с |
| Кнопка не привязалась | «Кнопка поставлена, но скрипт не назначился на листах: … — назначьте вручную» | 8 с |

Остались только два **модальных `ui.prompt`** — в диалоге «Вернуть из архива»: они нужны для ввода Position ID и причины, всплывающее сообщение ввод принимать не умеет.

`toast` нельзя вызвать из контекста без UI (например, из часового триггера): вызов обёрнут в `try/catch` — сообщение не показывается, факт пишется в `SYSTEM_LOG`, работа не падает (проверено `v12_ui_test` B8–B10).

### 5.2 Кнопка «ПРИМЕНИТЬ» в верхнем левом углу листа

Настоящую кнопку **поверх сетки** листа в Google Sheets можно создать только картинкой. Реализовано полностью скриптом — без внешних файлов и без ручных шагов:

- картинка (124×20, зелёная, белый текст «ПРИМЕНИТЬ») хранится **в коде в base64** (PNG сгенерирован офлайн растровым шрифтом 5×7 и закодирован вручную: zlib + CRC32) и вставляется через `Sheet.insertImage(blob, 1, 1, 2, 1)` — якорь **A1**, то есть верхний левый угол листа;
- скрипт кнопке назначается **программно**: `OverGridImage.assignScript("v12ApplyChangesUI")` — тот же код, что и у пункта меню (проверено по официальной документации Apps Script: `assignScript` доступен);
- колонка A расширяется до 130 px, поэтому кнопка **не перекрывает** заголовок соседней колонки; данные (Position ID) в колонке A видны ниже, со строки 2;
- кнопка ставится на три рабочих листа — **Сводка дефицитов**, **ОТБОРКА**, **WORKING BOM** (`V12_UI.BUTTON_SHEETS`);
- alt-подпись картинки: «Применить изменения (очередь PENDING_EDITS)».

Идемпотентность и восстановление:

- `v12InstallApplyButton()` перед вставкой **удаляет** прежнюю кнопку — и только картинку, назначенную на `v12ApplyChangesUI` (пользовательские картинки не трогаются), поэтому повторный запуск не плодит копии;
- если `assignScript` не подтвердился (проверяется через `getScript()`), лист попадает в список `unbound`, пишется `WARNING`, а пользователю показывается сообщение с инструкцией привязать скрипт вручную;
- `v12Install` ставит кнопку автоматически; отдельный пункт меню **«Восстановить кнопку «Применить»»** → `v12InstallApplyButtonUI` переустанавливает её без полной установки;
- `v12RemoveApplyButton()` — удаление кнопок со всех листов.

## 6. Надёжность: что улучшилось

- Устранена первопричина «сброса введённых значений»: нет пересборки проекций во время набора — окна гонки нет по построению, а не «сужено».
- Применение **атомарно и детерминировано**: один вход, один лок, один пересчёт.
- Исчезло поведение «то мгновенно, то через минуту» (`onEdit` больше не пытается применить правку сам).
- Пользователь больше не видит «Система занята обновлением»: модальных окон в пути правки нет вовсе.
- Меньше запусков скрипта → меньше расхода квот Apps Script и меньше записей в лог.
- Очередь — первичный источник истины: значение не теряется, даже если ячейку успела перезаписать любая пересборка (регрессия закрыта тестом Z8b).

**Риски и их митигация:**

| Риск | Митигация |
|---|---|
| «Забыл нажать Применить» | Ячейка-индикатор + счётчик в подписи меню; введённые значения видны в ячейках до применения |
| Многопользовательская работа | last-wins по `(SOURCE, POSITION_ID, FIELD)` сохранён; Apply применяет **все** накопленные намерения (в т.ч. чужие) — это осознанный выбор: очередь не «зависает» из-за чужой правки |
| Две пачки Apply подряд | Вторая — no-op (первая помечает строки `DONE`), идемпотентность проверена тестом Z4 |

## 7. Скорость

- **Средняя — выросла:** серия из N правок теперь даёт **ровно один** пересчёт проекций вместо нескольких (раньше `v12SetOrderedQty` при заполненной дате тянул ещё и полную пересборку СНАБЖЕНИЯ + Dashboard).
- **Латентность самого Apply не изменилась:** это по-прежнему полный пересчёт 5 листов (`clearBody` + `writeValues` + переустановка чекбоксов/цветов/фильтра). Кнопка **сокращает число** пересчётов и делает их предсказуемыми, но не ускоряет пересчёт.
- Из «горячего пути» навсегда убраны: пересборки внутри обработчиков одиночных правок, гейт лока и таймауты в `onEdit` (для редактируемых полей), подбор правок из листов (harvest).
- **Чтобы ускорить сам Apply**, нужны инкрементальные проекции — пересборка только затронутых строк (для Сводки заготовка уже есть: `v12RefreshDeficitSummaryRow`; аналоги нужны для ОТБОРКИ / WORKING BOM / СНАБЖЕНИЯ / Dashboard). Это отдельная, более крупная задача.

## 8. Что НЕ изменилось

- `v12RefreshProjections` (полная пересборка 5 листов) — по-прежнему центр стоимости.
- Часовая `v12ScheduledUpdate` → `v12RunFullSync` (импорт исходных BOM из Drive) — вне темы V3.
- Схема «редактируемые ячейки живут внутри проекции» — сохранена (именно она порождает обратную запись в `POSITION_STATE`; полное упрощение потребовало бы вынести ввод в отдельный лист-форму).
- Правки физического склада (`MATERIAL_STATE.WAREHOUSE_QTY`), чекбокс «Выполнено» дашборда и фильтр проекта в `ОТБОРКЕ` — применяются немедленно (под локом), как и раньше.

## 9. Развёртывание

1. Выгрузить код (`clasp push`) — включая новый файл `v12_ui.js`.
2. **Один раз** выполнить `v12Install` — он удалит устаревший минутный триггер `v12ScheduledQueueDrain` (имя обработчика внесено в `removeV11Triggers`), поставит актуальные триггеры (`v12OnEdit` + часовая `v12ScheduledUpdate`) и **поставит кнопку «ПРИМЕНИТЬ»** на три рабочих листа. По завершении появится всплывающее сообщение «Скрипт выполнен: V12 установлена…».
3. Ничего переносить не нужно: лист `PENDING_EDITS` и его схема не менялись.

Порядок работы пользователя: ввести/отметить данные → нажать зелёную кнопку **«ПРИМЕНИТЬ»** в верхнем левом углу листа (или пункт меню) → увидеть всплывающую сводку применённых/неприменённых изменений в правом нижнем углу.

Если кнопка была удалена вручную или не появилась (например, при первом развёртывании без `v12Install`) — пункт меню **«Восстановить кнопку «Применить»»**.
