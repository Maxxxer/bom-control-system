# Исправление: «Отметка получено» фиксируется не полностью (38 галочек ↔ 29 строк в PENDING_EDITS)

> Разбор дефекта — в `project_info__59.md`. Здесь — реализованные изменения, их причины и верификация.

## Причина (кратко)
Fix `58` вернул захват к «точному» режиму (пишет **только** строки события `onEdit`), а «добор всех отмеченных галочек» (`v12RebuildPendingFromChecked`) вызывался **только** при нажатии «Применить». Поэтому между отметкой и Apply лист `PENDING_EDITS` содержал столько строк, сколько событий `onEdit` «доехало» — 29 из 38. Отсутствующие 9 добирались лишь в момент применения.

## Реализовано

### 1. Самовосстановление захвата (главный фикс) — `v12_queue.js`
Добавлена `v12ReconcilePendingHandoffs()` — идемпотентная **пересборка** множества HANDOFF-намерений по ФАКТИЧЕСКИМ галочкам ОТБОРКИ/WORKING BOM **под локом**, с `SpreadsheetApp.flush()` (через `v12RebuildPendingFromChecked`). Возвращает число добавленных строк либо `null`, если лок занят (тогда пересборку добьёт следующее событие или Apply).

В `v12CaptureCheckboxEdit` (быстрый путь `onEdit` для ОТБОРКИ/WORKING BOM), **после** фиксации строк события, добавлен вызов:

```js
if (pendingRows.length) {
  v12EnqueuePendingRows(pendingRows);
}
// САМОВОССТАНОВЛЕНИЕ очереди...
v12ReconcilePendingHandoffs();
return true;
```

**Следствие:** лист `PENDING_EDITS` отражает **все** отмеченные галочки **сразу**, ещё до «Применить». Даже если Google «проглотил» часть событий при массовой отметке, любое доехавшее событие ре-сканирует лист и добирает недостающие. Дубли по-прежнему невозможны — `v12RebuildPendingFromChecked` схлопывает ключи и добавляет только отсутствующие.

### 2. Смягчение молчаливого сброса при занятом локе — `v12_queue.js`
`v12EnqueuePendingRows` теперь делает **одну короткую повторную попытку** взять лок (пауза 300 мс через `Utilities.sleep`, если доступен), и только при повторной неудаче — безопасный отказ с `WARNING` (как раньше). Это снимает часть потерь намерений при конкуренции с параллельным `onEdit`/применением.

### 3. Единый Edit ID при пересборке — `v12_queue.js`
В `v12RebuildPendingFromChecked` строки, добавленные пересборкой, получают Edit ID из **одной ленивой базы** (`editIdBase + "-rbN"`); база генерируется **только при наличии строк к добавлению** — чтобы не тратить лишний RPC `Utilities.getUuid()` на пачке без потерянных галочек (сохраняет инварианты теста производительности P5).

### 4. Пункт меню «Пересобрать очередь» — `v12_controller.js`
- В меню `BOM CONTROL V12` добавлен пункт **«♻ Пересобрать очередь (по галочкам)»** → `v12RebuildPendingFromCheckedUI`.
- Добавлена `v12RebuildPendingFromCheckedUI()`: вызывает `v12ReconcilePendingHandoffs()`, обновляет индикатор неприменённых изменений и показывает toast («Очередь пересобрана: дополнено N, всего в очереди M намерений»; при занятом локе — «повторите через несколько секунд»).

## Поведение до/после

| | До | После |
|---|---|---|
| Строк в `PENDING_EDITS` до Apply | = число доехавших событий (29 из 38) | = число фактических галочек (38) |
| Дубли при перекрытии событий | нет (точный захват) | нет (пересборка схлопывает ключи) |
| Потерянные события | восстанавливались только на Apply | восстанавливаются сразу при любом доехавшем событии; Apply — как страховка |
| Молчаливый сброс при занятом локе | сразу отказ | 1 повтор, затем безопасный отказ |
| Ручной контроль | — | пункт меню «Пересобрать очередь» |

- Захват **по-прежнему фиксирует строки события** (быстро, детерминированно), а «добор всех галочек» идёт пересборкой — это устраняет и потери, и дубли одновременно.
