# Исправление: «освободившиеся» строки сохраняли цвет удалённых позиций

> Пользователь: в «Сводке дефицитов» и «ОТБОРКЕ» при удалении позиций строки ниже нового числа данных остаются залитыми цветом прежних позиций. Нужно, чтобы свободные строки становились БЕЛЫМИ.

## Причина

Пересборка проекции (`v12RefreshDeficitSummary`, `v12RefreshPicking`, `v12RefreshWorkingBOM`, `v12RefreshDashboard`) очищает тело листа через `v12ClearBody` → `clearBody` → `clearRange`, который вызывал **`range.clearContent()`**. У `Range.clearContent()` очищаются **значения**, но **НЕ фон** (заливка — раздельное форматирование).

Затем цвет наносится функциями `v12ApplyDeficitColors(rows)` / `v12ApplyPickingColors(colors)` / `v12ApplyDashboardStatusColors(...)`, которые красят **только `rows.length` строк** (актуальные данные). Строки НИЖЕ нового числа данных не перекрашивались → сохраняли заливку предыдущего (более длинного) состояния, если позиции были удалены.

## Исправление (одно место, для всех проекций)

`sheet_service.js` → `clearRange`: после `clearContent()` дополнительно выставляется **белый фон** на весь очищаемый диапазон:

```js
const range = sheet.getRange(row, col, numRows, numCols);
range.clearContent();
// Сброс ЗАЛИВКИ в БЕЛЫЙ: clearContent() очищает значения, но НЕ фон. При
// сокращении числа строк «освободившиеся» строки иначе сохраняли бы заливку
// прежних позиций (Сводка дефицитов / ОТБОРКА / WORKING BOM / Dashboard).
if (typeof range.setBackground === "function") {
  range.setBackground("#FFFFFF");
}
```

Порядок безопасен: `clearBody` выполняется **до** записи строк, поэтому затем проекция записывает новые данные и перекрашивает **свои** строки (`v12Apply*Colors`), а «хвост» ниже новых данных остаётся белым. Затрагивается заодно Dashboard и Supply — единообразно.

`clearRange` вызывается только из `clearBody` (проверено), поэтому изменение локально по эффекту и не влияет на запись данных.
