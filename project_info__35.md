## Что исправлено в этой волне

### B-12 — `toNumber` разбирал только первую запятую 🔴→✅
`utils.js :: toNumber` заменял ТОЛЬКО первую запятую на точку, из-за чего «1,234.56»
парсилось как 1.234 (важно при импорте цен/количеств). Реализован разбор разделителей:
- «1,234.56» (запятая — тысячи) → 1234.56;
- «1.234,56» (точка — тысячи) → 1234.56;
- «1,5» (запятая — десятичный) → 1.5;
- «1.234.567» / «1,234,567» → 1234567;
- boolean → 1/0.
Эвристика: если присутствуют оба разделителя — десятичным считается ПРАВЫЙ.

### C-4 — `v12RevertEdit` молча ничего не делал для диапазона 🔴→✅
`v12_trigger.js :: v12RevertEdit`: для одиночной ячейки восстанавливает значение по
`e.oldValue` (как раньше). Для ДИАПАЗОНА `oldValue` недоступен, точный откат технически
невозможен — раньше это было «молчаливым no-op». Теперь такой случай явно пишется в
SYSTEM_LOG с уровнем WARNING (обработчики диапазонов чекбоксов откатывают свои ячейки
самостоятельно).

### P-6 — ОТБОРКА читала Position ID по одной ячейке в цикле 🟠→✅
`v12HandlePickingRangeEdit` теперь читает колонку Position ID ОДНОЙ выборкой
(`getRange(firstRow, POSITION_ID, numRows, 1).getValues()`), а не N одиночных чтений.
(В `v12HandleDeficitRangeEdit` это уже было сделано в первой волне.)

### P-7 — POSITION_STATE читался дважды за пересчёт 🟡→✅
`v12RefreshProjections` теперь читает POSITION_STATE ОДИН раз и передаёт данные в
harvest (`v12HarvestDeficitInput(skip, posData)` / `v12HarvestPickingInput(posData)`).
Повторное чтение делается ТОЛЬКО если harvest реально что-то исправил (страховка от
пропущенного onEdit) — harvest возвращает boolean-признак изменений.

## Осознанно НЕ менялось (проектные решения, не дефекты)

- **B-2** (чекбокс ОТБОРКИ односторонний): успешная передача архивирует позицию и
  вычитает склад, поэтому «снятие галочки» после пересборки недостижимо; обратный
  путь — меню «↩ Вернуть из архива».

- **B-4** (передача уменьшает склад на `required`): величина ≤ `available`, а склад по
  инварианту ≥ `reserved`; кламп до 0 — защита, а не источник искажений.
- **B-5** (`Реальная поставка` фиксирует полную потребность): в листе это ЧЕКБОКС
  (осознанный выбор схемы); частичная поставка — изменение UX/схемы.
- **B-6** (harvest поставки только «вверх»): намеренно, чтобы не сбрасывать уже
  сохранённые (в т.ч. частичные) поставки.
- **B-10** (СНАБЖЕНИЕ/Dashboard обновляются, когда заданы и «Заказано», и «Ожидаемая
  поставка»): компромисс по производительности (полный пересбор этих листов на каждый
  ввод был бы дорогим).
- **B-11** (RBAC выключен при пустом `V12_ROLE_MAP`): «работает из коробки»; при
  заполнении карты пользователь вне карты теряет доступ — заполняйте карту полностью.
- **C-3** (реентрантность лока на модуль-глобалах): корректна в одном исполнении;
  замечание о хрупкости оставлено в коде.
- **P-8** (`flush()` вызывается несколько раз на правку): каждый вызов привязан к
  «опасному» чтению после записи; сокращение — микро-оптимизация с риском.
- **P-9** (guard `_v12ProjectionUiState`): модуль-глобалы Apps Script не переживают
  запуски; guard безопасен, его польза ограничена одним исполнением.
