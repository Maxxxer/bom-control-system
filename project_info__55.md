# Дефект захвата «Отметки получено» в ОТБОРКЕ — причины и исправление

> Отчёт сохранён в `project_info__54.md`. Это дефекты **этапа захвата** (`v12OnEdit` → `v12CaptureCheckboxEdit` → `v12EnqueuePendingRows`), не связанные с моими оптимизациями (они — на этапе применения).

## Как идёт захват
1. Отметка чекбокса в ОТБОРКЕ (кол. `CHECKBOX` = 12) → `v12OnEdit` (`v12_trigger.js`).
2. `v12CaptureCheckboxEdit(e,"ОТБОРКА")` (`v12_queue.js`): проверка колонки 12 → роль → значения чекбоксов из `e.value`/`e.values` → **отдельное** чтение `Position ID` (кол. 1) → `v12BuildPendingRow` на каждую непустую позицию → `v12EnqueuePendingRows`.
3. `v12EnqueuePendingRows`:
```js
const sheet = v12GetSheetByKey("PENDING_EDITS");
const startRow = sheet.getLastRow() + 1;   // ← ГОНКА
writeValues(sheet, startRow, 1, rowArrays);
v12UpdatePendingIndicator();
```

## Причины (по значимости)

**1. Потеря строк из-за гонки записи (главная — «не все позиции попадают»).**
`v12EnqueuePendingRows` не сериализован и вычисляет `startRow = getLastRow() + 1`. При быстрых/массовых отметках Google запускает `onEdit` несколько раз почти одновременно; два исполнения читают **один и тот же** `getLastRow()` и пишут в **одну и ту же** строку `K+1` — вторая запись **перезатирает первую**. Позиция «пропадает»: чекбокс стоит, а намерения нет. Усугубляют: **в быстром пути onEdit нет лока** (так и задумано в V3); `v12BuildPendingRow` вызывает `generateEventId()` = `Utilities.getUuid()` **на каждую строку** (RPC → долгий захват → больше перекрытий); `v12UpdatePendingIndicator()` тут же читает лист ещё раз.

**2. Очередь append-only → «off и on сразу».**
`v12EnqueuePendingRows` только **добавляет** и не схлопывает прежнее намерение по ключу `(SOURCE, POSITION_ID, FIELD)`. «Снял» → строка `false`, «поставил» → ещё строка `true`. Обе лежат до Apply, а last-wins определяется **порядком строк**, который при гонке может быть перепутан → применение решает «отмена», хотя галочка стоит. Отсюда и ощущение двойной отметки.

**3. Строки без Position ID / «фантомные» чекбоксы (вторичная).**
`v12CaptureCheckboxEdit` пропускает строки с пустым `Position ID` (`if (!positionId) continue;`). При протяжке диапазона на пустые/пограничные строки чекбокс стоит, а намерения нет.

**4. Рассинхрон «значение чекбокса» ↔ «Position ID» (вторичная).**
Значения чекбоксов — из события, а `Position ID` — **отдельным живым чтением** после события. Если лист успел перестроиться (`v12RefreshPicking` при чужом Apply очищает тело и пишет чекбоксы=`false`, строки могут переупорядочиться), `idColumn[r]` может не совпасть со строкой `firstRow+r` → намерение уходит на «соседнюю» позицию, нужная отсутствует.

## Предлагаемое исправление

**Fix 1 (обязательный). Лок + перечитывание `getLastRow()` под локом** в `v12EnqueuePendingRows`:
```js
const lock = acquireScriptLock({ tryOnly: true, timeoutMs: 10000 });
if (!lock) { logSystem(...,"Очередь занята, намерение не зафиксировано","WARNING"); flushSystemLog(); return; }
try {
  const sheet = v12GetSheetByKey("PENDING_EDITS");
  const startRow = sheet.getLastRow() + 1;   // ПОД локом
  writeValues(sheet, startRow, 1, rowArrays);
} finally { lock.releaseLock(); }
```
Лок короткий — только запись строки, проекции не пересобираются (гонку с пересборкой не возвращает).

**Fix 2. Upsert вместо append** — искать существующую `PENDING`-строку по `(SOURCE, POSITION_ID, FIELD)` и обновлять её (`VALUE`/`USER`/`DATE`); если нет — дописывать. Тогда «снял→поставил» = одна строка `true`, и применение детерминировано.

**Fix 3 (страховка). Реконсиляция при Apply** — в `v12DrainPendingEdits` просканировать колонку `CHECKBOX` ОТБОРКИ/WORKING BOM: строки с `true` без намерения HANDOFF в очереди трактовать как передачу. Гарантирует инвариант **«галочка стоит ⇒ позиция передана»**, даже если `onEdit` был потерян. Один проход на пачку — дёшево.

**Fix 4 (ускорение захвата).** Не генерировать `Utilities.getUuid()` на каждую строку — один `Edit ID` на пачку (+ локальный суффикс) или локальный счётчик; сокращает окно гонки.

**Fix 5 (устойчивость).** Брать `Position ID` и значения чекбоксов из **одного** снимка диапазона `getRange(firstRow,1,numRows,numCols).getValues()` (без промежуточного перестроения).

## Рекомендуемый минимум
Fix 1 (устраняет пропажу строк) + Fix 2 (устраняет «off+on») + Fix 3 (страховка «галочка ⇒ передача»); Fix 4/5 — попутно.

## Важно не сломать
- Быстрый путь onEdit не должен тянуть пересборку проекций (лок — только на запись строки).
- Идемпотентность `v12MarkReceivedByProduction`, «передача только вверх», last-wins — сохраняются; Fix 2 делает очередь детерминированной.
- `v12CaptureDeficitEdit` (Сводка) должен использовать те же лок/upsert единообразно.

**Затронутые файлы:** `v12_queue.js` (`v12CaptureCheckboxEdit`, `v12CaptureDeficitEdit`, `v12EnqueuePendingRows`, `v12BuildPendingRow`, `v12DrainPendingEdits`), при необходимости `v12_trigger.js`, `utils.js`.
