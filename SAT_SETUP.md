# Настройка и работа: пошаговая инструкция

Продолжение `SAT_README.md` (зачем нужен сателлит и состав файлов).
Диагностика — в `SAT_TROUBLESHOOTING.md`.

---

## 3. Настройка мастера (администратор, один раз)

### 3.1. Развернуть код мастера

```bash
clasp push
```

> Файлы сателлита (`sat_*.js`, `sat_appsscript.json`, `SAT_*.md`) при этом НЕ
> выгружаются в мастер: они исключены в `.claspignore`.

### 3.2. Проверить области доступа

В `appsscript.json` мастера должны быть:
`.../auth/spreadsheets`, `.../auth/script.scriptapp`,
`.../auth/script.external_request`. Последняя обязательна — без неё мастер не
ответит сателлитам.

### 3.3. Выполнить установку

Мастер-таблица: меню **BOM CONTROL V12 → ⚙ Установка V12**.
Создаются два листа:

* `PICKING_BATCHES` — журнал лотов (кто, когда, проект, что применено);
* `PICKING_CLAIMS` — мягкие захваты проектов;

и `PENDING_EDITS` расширяется до 12 колонок (`Batch ID`, `Проект`).

### 3.4. Задать секрет отборщиков

Меню **BOM CONTROL V12 → 🔐 Задать/сменить секрет отборщиков**.
Появится всплывающее сообщение с секретом вида `PBT-…`. **Скопируйте его** —
он нужен каждому отборщику.

> Секрет хранится только в свойствах скрипта мастера и никогда не попадает в
> код, журналы и аудит. Смена секрета немедленно отключает старые личные файлы.

### 3.5. Развернуть веб-приложение

1. Редактор Apps Script мастера → **Развернуть → Новое развёртывание**.
2. Тип: **Веб-приложение**.
3. **Запуск от имени**: *От вашего имени* (`USER_DEPLOYING`) — обязательно.
4. **Доступ**: *Все, у кого есть аккаунт Google*.
5. Скопировать **URL веб-приложения** (заканчивается на `/exec`).

Проверка: открыть этот URL с `?action=health` — ожидается
`{"ok":true,"service":"BOM CONTROL V12",…}`.

### 3.6. Проверить роли отборщиков

В `v12_roles.js` (`V12_ROLE_MAP`) у каждого отборщика должна быть роль
`warehouse` или `production` (или `admin`) — иначе мастер ответит
`forbidden:no_role`.

### 3.7. Режим витрины для мастерского листа ОТБОРКА

Меню **BOM CONTROL V12 → 🛡 Поставить защиту на лист ОТБОРКА**.
Лист получает защиту-предупреждение и надпись «Витрина. Рабочее место — личный
файл отбора».

> Защита именно **мягкая**: жёсткий запрет сломал бы пересборку проекций, так
> как `v12RefreshPicking` пишет на этот же лист от имени нажавшего «ПРИМЕНИТЬ».

## 4. Настройка личного файла отборщика

### 4.1. Создать файл и проект скрипта

1. Создайте Google-таблицу, например «Отборка — Иванов».
2. **Расширения → Apps Script**.
3. Перенесите в проект файлы из корня репозитория:
   `sat_config.js`, `sat_api.js`, `sat_sheet.js`, `sat_refresh.js`,
   `sat_submit.js`, `sat_menu.js`, `sat_install.js`.
4. Содержимое `sat_appsscript.json` положите как `appsscript.json` этого
   проекта (⚙ Настройки проекта → показывать файл манифеста).
   Ключевая область — `.../auth/script.external_request`.

> Через clasp: скопируйте `sat_*.js` и `sat_appsscript.json` в отдельную папку,
> `clasp create --type sheets`, переименуйте манифест в `appsscript.json`,
> затем `clasp push`.

### 4.2. Выполнить установку

В таблице: **Отбор → 🧩 Установка (лист, триггеры, кнопка)**.
Google запросит разрешения (таблица, внешние запросы, триггеры) — это ожидаемо.

Создаются:

* лист **ОТБОРКА** с заголовками и фильтром в `B1`;
* кнопка **ПРИМЕНИТЬ** в левом верхнем углу;
* два триггера: обновление при открытии файла и при смене `B1`.

### 4.3. Заполнить настройки

Меню **Отбор → ⚙ Настройки файла отбора** — три запроса подряд:

| Поле | Значение |
|---|---|
| Адрес веб-приложения мастера | URL из п. 3.5 (заканчивается на `/exec`) |
| Секрет отборщиков | строка `PBT-…` из п. 3.4 |
| Ваш рабочий e-mail | адрес из `V12_ROLE_MAP` мастера |

Итог: «Настройки сохранены. Проектов доступно: N».

### 4.4. Чек-лист готовности

- [ ] В `B1` — выпадающий список проектов, в `A1` — «Проект →»
- [ ] Кнопка «ПРИМЕНИТЬ» на месте; без галочек сообщает «Нет отмеченных позиций»
- [ ] «О программе» показывает адрес мастера, e-mail и «Секрет: задан»
- [ ] В колонке «Отметка получено» есть флажки
- [ ] Справа от таблицы видно уведомление «Проект: … Позиций: N»

## 5. Ежедневная работа отборщика

1. Откройте свой файл — список обновится автоматически.
2. В `B1` выберите проект (или «(Все проекты)»).
3. Поставьте галочки в колонке **«Отметка получено»**.
4. Нажмите **«ПРИМЕНИТЬ»** — мастер применит только ваши отметки и вернёт итог.
5. Список обновится сам: применённые позиции исчезнут.

### Что происходит при нажатии

* Галочки собираются в **лот** (номер вида `SAT-20260917-114512-…`).
* Мастер пишет намерения с привязкой к номеру лота и применяет только его.
* Результат — в `PICKING_BATCHES`; галочки снимаются только за применённые
  позиции (остальные остаются для разбора).

### Смысл сообщений

| Сообщение | Действие |
|---|---|
| «передано производству N» | Работа принята |
| «<позиция> — уже передано производству» | Ранее передал другой отборщик |
| «<позиция> — позиция исчезла — обновите список» | BOM обновился, проверьте заново |
| «Мастер синхронизируется… повторите» | Галочки сохранены, повторите позже |
| «Лот принят и будет применён…» | Можно закрыть файл, итог — «Статус лота» |

### Двойное нажатие безопасно

Повторная отправка того же набора в течение 2 минут использует тот же номер
лота, а мастер повторный лот не применяет — возвращает прежний результат.

## 6. Конфликты и как они решены

| № | Конфликт (был) | Решение |
|---|---|---|
| 1 | Общий фильтр проекта в `B1` | У каждого свой `B1` в своём файле |
| 2 | Пересборка листа стирала чужие галочки | Витрина обновляет только колонки 1–12; галочки сопоставляются по `Position ID` |
| 3 | Общая очередь: «ПРИМЕНИТЬ» сливал чужую работу | Каждая отправка — лот; мастер применяет только его |
| 4 | Потеря намерения при занятом замке | Повторы и атомарная дописка в очередь — намерение не теряется |
| 5 | Правка склада вне очереди стирала галочки | Правка складского остатка больше не пересобирает проекции |
| 6 | Гонка «ПРИМЕНИТЬ» ↔ синхронизация | Синхронизация — ночью; на время флага приём лотов отклоняется |
| 7 | Двойная выдача одного материала | Не защищена сознательно (склад не входит в доступность); риск виден через захваты |
| 8 | Уход складского остатка в минус | Оставлено как есть; расхождения видны в «Проверке консистентности» |
| 9 | Двое на одном проекте | Мягкий захват: предупреждение, работа продолжается, захват истекает сам |
| 10 | Коллизия по одному `Position ID` | Порядок применения сохраняется; дубли гасятся пунктом «Схлопнуть дубли очереди» |

### Почему захват мягкий

Запрет «проект занят — работать нельзя» вреден: двое иногда осознанно делят
большой проект, а забытый захват навсегда остановил бы работу. Система
предупреждает и позволяет продолжить; захват снимается сам по TTL, а также
вручную — отборщиком («Освободить проект») или администратором
(меню мастера → «🔓 Освободить все захваты проектов»).

### Где что смотреть в мастере

| Лист | Содержимое |
|---|---|
| `PICKING_BATCHES` | журнал лотов: номер, время, отборщик, проект, файл, статус, применено/всего |
| `PICKING_CLAIMS` | захваты: проект, отборщик, взят, истекает, статус |
| `PENDING_EDITS` | намерения; колонки «Batch ID» и «Проект» привязывают их к лоту |
