# BOM CONTROL SYSTEM V12 — Анализ задачи «Фильтр-выпадающий список по BOM в листе „Сводка дефицитов“»

> **Режим:** Explore. Ниже — не реализация, а разбор кодовой базы под конкретную задачу и точная карта изменений для Act Mode.

---

## 1. Формулировка задачи (как её надо понимать в терминах кода)

В листе **Отборка**

1. Вместо **надписи `BOM`** (заголовок колонки 2, ячейка `B1` первой строки) вставить **выпадающий список** (dropdown / data validation), который служит **фильтром** по этой же колонке `BOM`.
2. В список должны попадать **только буквенно-цифровые коды агрегата** — это **первая часть названия BOM до первого дефиса** (`bomName.split("-")[0]`).
3. Выбор проекта → на листе остаются **только позиции этого проекта** (остальные скрываются/не показываются).
4. Сортировка результата:
   - **первично — по колонке `BOM`** (внутри выбранного проекта);
   - затем — **по доступности материала: материал на складе — сверху**;
   - затем — **по номерам позиций в BOM** (`BOM_ROW`, кол. 3, поле `POSITION_COLUMNS.BOM_ROW`).

### 2.2. Как формируется тело листа

**`v12RefreshDeficitSummary()`** — `v12_projections.js` (ключевая функция):

```js
function v12RefreshDeficitSummary() {
  v12HarvestDeficitInput();                 // подбор необработанных правок из листа -> POSITION_STATE
  const data = v12ReadSheet("POSITION_STATE");
  const rows = [];
  for (let i = 1; i < data.length; i++) {
    const r = data[i];
    if (!v12IsDeficitRowActive(r)) continue;   // <-- ФИЛЬТР + условие «попадёт ли в сводку»
    rows.push(v12BuildDeficitRow(r));           // <-- ПОРЯДОК строк = порядок в POSITION_STATE
  }
  v12ClearBody("DEFICIT_SUMMARY");               // чистит строки 2..N (заголовок 1 сохраняется!)
  if (rows.length) v12WriteRows("DEFICIT_SUMMARY", 2, rows);
  v12InstallDeficitCheckboxes(rows.length);     // чекбокс «Реальная поставка» (кол. 12)
  v12ApplyDeficitColors(rows);                  // окраска по статусу
}
```

- **`v12IsDeficitRowActive(r)`** (`v12_projections.js`) — фильтр видимости строки. Возвращает `false` если:
  - `LIFECYCLE_STATE` = `ARCHIVED` или `REMOVED`;
  - `RECEIVED_BY_PRODUCTION === true` (уже передано);
  - `availableQty >= requiredQty` (материал уже на складе) **или** `DEFICIT_QTY <= 0`.
  То есть сейчас в сводку попадают **только позиции с дефицитом > 0 и не готовые к передаче**.
- **`v12BuildDeficitRow(r)`** — собирает массив из 14 значений из строки `POSITION_STATE`. Кол. 2 = `r[P.BOM_NAME - 1]`.

**`v12RefreshDeficitSummaryRow(positionId, committedKey)`** — точечное обновление одной строки (важно не сломать при фильтре/сортировке — см. §5.6).

**`v12ClearBody("DEFICIT_SUMMARY")`** (`sheet_service.js`) чистит **только тело (со строки 2)**, строку заголовков `1` не трогает — поэтому dropdown в `B1` при пересборке **не будет стёрт**.

### 2.3. Как лист создаётся и форматируется

- **`v12EnsureAllSheets()`** → `ensureSheet(name, header)` (`sheet_service.js`): заголовки пишутся **только если лист пуст** (`getLastRow() === 0`). То есть `HEADERS.DEFICIT_SUMMARY` (включая `"BOM"`) пишется один раз.
- **`v12FormatAllSheets()`** (`v12_sheet_service.js`): `setFrozenRows(1)` + жирный шрифт строки 1. Заголовок **не перезаписывается**.
- Установка всего — из меню: `v12OnOpen()` (`v12_controller.js`) → пункт «⚙ Установка V12» → `v12Install()` → `v12EnsureAllSheets()`.

### 2.4. Как лист связан с `onEdit`

**`v12OnEdit(e)`** (`v12_trigger.js`) маршрутизирует правки по листам. Для сводки:

- одиночная ячейка → **`v12HandleDeficitEdit(e)`**;
- диапазон (вставка/автозаполнение) → **`v12HandleDeficitRangeEdit(e)`**.

`v12HandleDeficitEdit`:
```js
const positionId = sheet.getRange(row, D.POSITION_ID).getValue();  // кол. 1
if (!positionId) return;                                           // <-- для строки 1 (заголовок) выйдет сразу
// обрабатываются только кол. 9 (ORDERED_QTY), 10 (EXPECTED_DATE), 12 (REAL_DELIVERY)
// всё прочее -> v12RevertEdit(e) + лог "В сводке доступны только Заказ/Ожидаемая/Реальная поставка"
```

> ⚠️ **Важно для реализации:** если dropdown будет в `B1` (строка 1), то изменение этой ячейки сейчас **никак не обрабатывается** (нет `positionId` → ранний `return`). Понадобится **явная ветка** в `v12OnEdit`/`v12HandleDeficitEdit` на строку 1 / колонку 2, которая вызовет пересборку сводки по новому выбранному проекту.

## 3. Формат данных: откуда взялся «код агрегата»

- BOM читаются из Drive (`v12_source.js`, `v12ReadSourceBOM`): `bomName = file.getName().replace(/\.[^/.]+$/, "")` — **имя файла-источника без расширения**.
- `v12UpsertSourceBOM` использует это `bomName` как `BOM_ID` и `BOM_NAME` (поиск/создание записи в `BOM_REGISTRY` по имени).
- В `POSITION_STATE` колонки `BOM_ID` (2) и `BOM_NAME` (4) **совпадают** = имя файла BOM (см. `v12_position_state.js`, `v12BuildPositionRow`: `row[P.BOM_NAME-1] = sourceMaterial.bomName || bomId`).
- `BOM_ROW` (кол. 5) — номер строки позиции в исходном BOM (`sourceMaterial.row`).

**Следствие:** требуемый «буквенно-цифровой код агрегата — первая часть названия BOM до первого дефиса» нужно получать из `BOM_NAME` (или `BOM_ID`) через:
```js
function v12ExtractBomProjectCode(bomName) {
  return String(bomName || "").split("-")[0].trim();
}
```
Например, `"1234.АБВ-5678 Щит"` → `"1234.АБВ"`. Такой функции в коде **сейчас нет** — её надо добавить (логичное место — `v12_utils.js` рядом с `v12Norm`).

> Уточнить у пользователя: что считать «буквенно-цифровым» — оставить ли в списке коды, оканчивающиеся на `.`/пробел; включать ли опцию «Все проекты» для сброса фильтра.

## 5. Неочевидные поведения, риски и решения

### 5.1. Dropdown ≠ встроенный фильтр Google Sheets
Data validation (`requireValueInList`) **ограничивает ввод в одной ячейке**, но **не скрывает строки**. Чтобы «отфильтровать все позиции кроме проекта», нужно **перестроить тело сводки** (это ровно то, что делает проекция: `clearBody` + запись только подходящих строк). Встроенный Filter View здесь **не** подходит как основное решение: он не переживает пересборку листа кодом и не даёт «материал сверху» произвольной сортировкой диапазона.

### 5.2. Куда писать dropdown и где хранить выбор
Два варианта:
- **(A) В самой ячейке `B1`** (прямо как просит пользователь — «вместо надписи BOM»). Плюс: соответствует формулировке. Минус: `B1` перестаёт быть строкой «BOM», и любые обработчики/валидации заголовка надо не запускать для `B1`.
- **(B) В отдельной ячейке** (напр. `B1` для фильтра, а заголовок оставить в другой). Минус: не соответствует заданию.

Рекомендуется **(A)**: `setDataValidation(requireValueInList(codes))` на `B1`, значение по умолчанию — «(все)» или первый проект. Список кодов должен **обновляться** при изменении состава BOM (пересчитывать в `v12RefreshDeficitSummary`).

### 5.3. Сортировка — конкретика
Ключи (в порядке применения):
1. **BOM** (кол. 2) — строковое сравнение (локализованное; учесть числа/регистр через `localeCompare`).
2. **Доступность материала — «в наличии» сверху.** Ключ надо определить явно. Кандидаты из `POSITION_STATE`:
   - `AVAILABLE_FOR_PRODUCTION` (кол. 28) = `reserved + realDelivery`;
   - либо бинарный признак `availableForProduction >= requiredQty` (по `v12_calculate.js` это условие «готово к отдаче»).
   Т.к. `v12IsDeficitRowActive` сейчас **отсекает** такие строки (они уходят в ОТБОРКУ), «материал в наличии» в текущем фильтре **недостижим** → **это внутреннее противоречие**, требующее уточнения (см. §6).
3. **`BOM_ROW`** (кол. 3) — числовая сортировка.

### 5.4. Порядок строк и «harvest» правок
`v12HarvestDeficitInput()` (в начале `v12RefreshDeficitSummary`) подбирает введённые в лист значения и переносит их в `POSITION_STATE` **до** перезаписи листа. Он сопоставляет строки листа с позициями **по `POSITION_ID`** (кол. 1), а не по номеру строки, — поэтому **фильтрация и сортировка безопасны** для подбора (перестановка/скрытие строк не путает позиции).

### 5.5. Фильтр и чекбоксы
`v12InstallDeficitCheckboxes(rowCount)` ставит чекбоксы на первые `rowCount` строк тела. Если фильтр уменьшает число строк, ставить валидацию надо на **фактическое** число записанных строк (`rows.length`), а «хвост» ниже — очищать (`clearDataValidations`), иначе останутся чекбоксы на пустых строках. В текущем коде `maxRows = Math.max(lastRow - 1, rowCount)` — при фильтре это может «растянуть» валидацию; проверить и, при необходимости, поправить.

### 5.6. `v12RefreshDeficitSummaryRow` — самая хрупкая точка
Точечное обновление одной строки предполагает, что **порядок строк на листе = порядок активных строк `POSITION_STATE`**. Как только добавляется фильтр/сортировка, это соответствие ломается. В функции есть защита:
```js
if (currentId !== id) { v12RefreshDeficitSummary(); return; }  // безопасный полный пересчёт
```
→ либо расширить её (учитывать фильтр), либо сознательно принимать полный пересчёт при активном фильтре (проще, но медленнее). Это же касается и `v12SetOrderedQty`/`v12SetExpectedDate` (`v12_operations.js`), которые вызывают `v12RefreshDeficitSummaryRow`.

### 5.7. Производительность
`v12RefreshDeficitSummary` пересобирает **весь лист** при каждой пересборке. Фильтрация/сортировка в памяти дешёвы, но при больших объёмах каждая правка фильтра = полная перезапись. Это уже свойственно текущей архитектуре (К7 — «инкрементально, но пока полная пересборка»).

### 5.8. RBAC
Сейчас правки в сводке разрешены по ролям: `ORDERED_QTY`/`EXPECTED_DATE`/`REAL_DELIVERY` — `PROCUREMENT`. Смена фильтра — **не** изменение данных, но `v12OnEdit` для `B1` должен либо не требовать роли, либо ввести отдельное право (`v12CanEditField`), иначе у `VIEWER`/`WAREHOUSE` фильтр может не сработать.

## 6. Открытые вопросы к пользователю (важно для Act Mode)

1. **«Материал в наличии сверху» — что это в терминах полей?** Сейчас сводка (`v12IsDeficitRowActive`) **исключает** строки без дефицита / с `availableForProduction >= required`. Возможны два прочтения:
   - (a) сводка должна показывать **все** позиции проекта (в т.ч. «в наличии»), и тогда сортировка «в наличии сверху» осмысленна (это совпадает с формулировкой из `project_info__14/15.md` — «Сводка содержит ВСЕ материалы из BOM»);
   - (b) сводка остаётся «только дефицит > 0», а «в наличии» = «частично зарезервировано/частично доступно».
   Это **ключевая развилка**: от неё зависит, надо ли менять `v12IsDeficitRowActive`.
2. **Порядок внутри «в наличии»**: по какому полю (кол. 2 `BOM`, затем `BOM_ROW` — как в задании, либо по статусу)?
3. **Пустой выбор / «Все проекты»**: нужна ли опция сброса фильтра?
4. **Где именно ячейка фильтра**: `B1` (замена «BOM») или отдельная ячейка рядом (напр. `B2`), чтобы сохранить заголовок?
