## Краткий вывод

Задача решается **в 4 файлах** и опирается на существующий механизм «проекций»: лист «Сводка дефицитов» (`DEFICIT_SUMMARY`) целиком пересобирается функцией `v12RefreshDeficitSummary()` из `POSITION_STATE`. Значит, «фильтр» — это не встроенный фильтр Google Sheets, а **перестройка тела листа** по выбранному коду проекта + сортировка. Заголовок колонки 2 сейчас — буквально строка `"BOM"` (`HEADERS.DEFICIT_SUMMARY[1]`, ячейка `B1`) — её и надо заменить на dropdown.

## 2. Как формируется тело листа (ключевая функция)

`v12_projections.js`, `v12RefreshDeficitSummary()`:
1. `v12HarvestDeficitInput()` — подбор введённых в лист значений обратно в `POSITION_STATE` (сопоставление **по `POSITION_ID`**, поэтому перестановка строк безопасна).
2. Читает `POSITION_STATE`, фильтрует через `v12IsDeficitRowActive(r)`, собирает строки `v12BuildDeficitRow(r)`.
3. `v12ClearBody("DEFICIT_SUMMARY")` — **чистит только строки ≥2**, заголовок `B1` сохраняется.
4. `v12WriteRows`, `v12InstallDeficitCheckboxes`, `v12ApplyDeficitColors`.

**Вывод:** фильтрация + сортировка встраиваются прямо в шаг 2 (до записи). Механизм уже готов к этому.

## 3. «Код агрегата до первого дефиса» — откуда брать

- `BOM_NAME` в `POSITION_STATE` = `BOM_ID` = **имя файла-источника BOM без расширения** (см. `v12_source.js` → `v12ReadSourceBOM`; `v12_position_state.js` → `v12BuildPositionRow`).
- Нужной функции парсинга **сейчас нет** — её надо добавить, например в `v12_utils.js`:
```js
function v12ExtractBomProjectCode(bomName) {
  return String(bomName || "").split("-")[0].trim();
}
```

## 5. Ключевые риски и противоречие

1. **Истинный фильтр нельзя сделать только data validation** — dropdown в ячейке не скрывает строки. Нужна перестройка листа (архитектура это позволяет).
2. **Противоречие по «в наличии сверху»:** сейчас `v12IsDeficitRowActive` **отсекает** позиции без дефицита / с `availableForProduction >= required` (они уходят в ОТБОРКУ). Значит строк «в наличии» в сводке сейчас **нет** — критерий сортировки требует уточнения (возможно, сводка должна показывать **все** позиции проекта — это совпадает с формулировкой из `project_info__14/15.md`).
3. **Хрупкая точка:** `v12RefreshDeficitSummaryRow()` (точечное обновление одной строки) предполагает, что порядок строк листа = порядок активных строк `POSITION_STATE`. Фильтр/сортировка это ломают — есть fallback на полный пересчёт, но его надо расширить. Затронет также `v12SetOrderedQty` / `v12SetExpectedDate` (`v12_operations.js`).
4. **Чекбоксы:** `v12InstallDeficitCheckboxes(rowCount)` ставит валидацию на `max(lastRow-1, rowCount)` строк — при фильтре может «растянуться» на пустые строки; проверять фактическое число записанных строк.
5. **RBAC:** правки в сводке привязаны к ролям (`PROCUREMENT`). Смена фильтра — не изменение данных; `v12OnEdit` для `B1` не должен требовать роль `PROCUREMENT`, иначе фильтр не сработает у других ролей.
